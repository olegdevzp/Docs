## 10. Frontend Standards, Performance & SEO

### 10.1 "What's your approach to frontend performance?"

**Answer:**

> I split **load performance** and **runtime performance**:
>
> **Load:** lazy routes, bundle analysis, tree-shaking, cache-friendly vendor chunks, image/asset optimization  
> **Runtime:** OnPush change detection, virtual scroll for long lists, throttle/batch stream updates, avoid unnecessary template work
>
> I measure with **realistic data** — not empty-state Lighthouse — because enterprise and content apps behave differently under load.

---

### 10.2 "What's your approach to testing?"

**Answer:**

> - **Unit tests:** services, pipes, RxJS logic — fast feedback
> - **Component tests:** critical flows, forms, error states
> - **Integration tests:** API boundaries with mocked backends
> - **E2E (selective):** happy paths for business-critical flows
>
> Bug fixes include a regression test. Shared library code gets **higher coverage** — highest leverage in a modular codebase.

---

### 10.3 "What does quality code mean to you?"

**Answer:**

> **Correct, readable, testable, and maintainable by someone who didn't write it.**
>
> Modular boundaries, typed API contracts, predictable state, clear error handling, and no hidden global side effects. Quality also means **operational readiness** — logging, feature flags, sensible loading states.
